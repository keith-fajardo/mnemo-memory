# ADR 0000: Short decision title

- **Status:** proposed
- **Date:** YYYY-MM-DD
- **Deciders:** names or roles
- **Issue:** issue or change identifier
- **Supersedes:** none
- **Superseded by:** none

## Context

Describe the user outcome, existing constraints, evidence, and forces that make a decision
necessary. Identify what is explicitly outside this decision.

## Decision

State the chosen design precisely enough that an implementation and an automated verification
can distinguish compliance from noncompliance. Identify ownership and affected boundaries.

## Alternatives considered

For each credible alternative, record its benefits, drawbacks, evidence, and reason it was not
selected. Include “defer the decision” when it is viable.

## Consequences

Record positive, negative, and neutral consequences. Include operational burden, compatibility,
failure modes, observability, and follow-up work.

## Security and privacy implications

Describe affected assets and trust boundaries, authorization order, data exposure, secret and
sensitive-data handling, deletion behavior, abuse cases, and required security tests. State
“none” only with justification.

## Token and cost implications

Describe effects on retrieved tokens, model input/output, embeddings, caching, local resources,
third-party calls, and ongoing cost. Identify the measurement that will validate the estimate.

## Dependency and licensing implications

List added, removed, or changed dependencies and transitive packages; their licenses, provenance,
owners, and replacement boundaries; or explain why the decision adds none. Link the dependency
register entries and any required notices.

## Reversal or migration strategy

Explain how to reverse the decision or migrate existing IDs, data, schemas, clients, and exports.
Identify compatibility windows, rollback tests, backup requirements, and irreversible portions.

## Verification

List automated tests, evaluation gates, security review, and operational evidence required before
acceptance and after rollout.

## References

Link only to Mnemo-owned contracts, standards, approved third-party documentation, evaluation
results, and related ADRs. Record source provenance for any external material.
